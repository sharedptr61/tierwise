Tierwise Head-to-Head
Evaluation report · November 2026 · measured costs, hidden tests, blind judging

Tierwise vs one model for everything

The same research and build jobs, done three ways: with Tierwise, which gives each step to the model it needs, with every agent on Opus, and with every agent on Fable. Tierwise ran three times; its results are the average. Every request was priced, every build ran against 19 hidden acceptance tests, and two judges scored the work without knowing who produced it.

2 · How Tierwise does it

Each step goes to the model it needs

Single-model approaches pay top price for every step. Tierwise reserves Fable for judgement-heavy evaluation and Opus for security-sensitive code and review, and gives reading, routine building and test runs to cheaper models.

      5 · Method and limits

      How the comparison was kept fair

      Identical conditions

      • The same workflow scripts, prompts, stages, reasoning effort per agent and review loop for every approach; only the model of each agent differed.
      • Every build started from its own byte-identical copy of the same code, and was scored by the same 19 hidden acceptance tests, written from the specification and never shown to the builders.
      • Two judges, one Opus and one Fable so neither model family grades only itself, saw anonymised outputs under shuffled letters with every model name and folder path removed, read them in opposite orders, and had to verify claims against the code.
      • Costs are every request priced by its own model and token type: uncached input, cache reads, 5-minute and 1-hour cache writes, output. The method reproduces Claude Code's own cost figures to the cent.

      Limits

      • Tierwise ran three times; all-Opus and all-Fable once each, on 26 November. Tierwise's runs followed on 27 November with the same scripts and prompts.
      • The judges scored Tierwise's runs together with the all-Opus and all-Fable outputs in one panel (with one output from an earlier Tierwise configuration, not shown), so all scores share a scale.
      • These runs measure Tierwise's model routing inside multi-agent workflows; they do not exercise the plugin's hooks or its check gate.
      • Savings at scale are projections: the measured per-job figures multiplied, assuming users do similar work.
      • Costs are list-price equivalents. On a subscription they are usage of the plan's limits, not a bill.
